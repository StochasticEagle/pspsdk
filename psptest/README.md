# PSPTEST

PSPTEST is PSPSDK's test declaration and runner framework. The persistent PSPDEV EBOOT is the only test orchestrator.

Generated test artifacts are not written into PSPSDK source trees. PSPDEV stage 6 discovers test sources in their owning repositories and builds all generated files below PSPDEV's ignored `build/` directory.

## Architecture

A PSPTEST PRX contains only:

- the package or SDK test functions;
- a static `PspTestSuite` descriptor;
- the minimal `module_start()` registration shim generated by `PSPTEST_MODULE(...)`;
- `module_stop()`.

A test PRX does not link `libpsptest.a`, create the PSPTEST worker thread, initialize or deinitialize libc/newlib, write result files, publish progress, or orchestrate its own lifecycle.

The persistent PSPTEST EBOOT links `libpsptest.a`. It loads a PRX, passes a binary `PspTestModuleRequest` to `sceKernelStartModule()`, receives the suite descriptor, creates the runner-owned test thread, executes the suite, records progress/results, then stops and unloads the PRX.

Tests that must be linked directly into the EBOOT use the same `PspTestSuite` and case API; their source remains in the normal owning repository and is compiled in place by PSPDEV stage 6.

## Module contract

Each PRX test lives in `psptest/<module>/` and contains a `Makefile.test`. It:

- builds as one user PRX;
- includes `psptest.h` but does not link `-lpsptest`;
- uses `PSPTEST_MODULE(...)`;
- emits no generated files into its source directory.

## Result format

The EBOOT writes:

```text
PSPTEST<TAB>1
SUITE<TAB>suite-name
CASE<TAB>PASS|FAIL|SKIP|INTERACTIVE_PASS|INTERACTIVE_FAIL<TAB>case-name<TAB>assertions=N[...]
SUMMARY<TAB>pass=N<TAB>fail=N<TAB>skip=N<TAB>total=N
```

## Coverage markers

Use `PSPTEST_COVERS(function_name);` at file scope for each public API exercised by a suite.
